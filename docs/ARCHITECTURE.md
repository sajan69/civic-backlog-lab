# Architecture and trust boundaries

The CLI separates acquisition, immutable import, SQL analysis and presentation. `fetch` is the only network client: it uses a fixed NYC source, bounded query shape and field projection. It writes a private local capture with a versioned manifest. Local JSON/CSV imports use the same normalized request model, independently of the collector. A raw-content hash and canonical context identify each observation; updated files become new snapshots rather than replacing a request's earlier state.

Validation and duplicate-conflict detection precede opening the database. A transaction covers snapshot metadata and normalized records. Unknown or contradictory outcomes remain inspectable through quality counts and are excluded from known-outcome denominators. Analysis selects exactly one snapshot, binds query parameters and reads packaged SQL. It never infers unsupported historical lifecycle transitions. Floating civil times remain separate from the UTC acquisition clock.

The export and dashboard layers consume the same aggregate analysis result. The browser server closes the database after computing a report and serves fixed in-memory representations. Filtering agency rows is a presentation operation, not a population query. JSON preserves provenance and warnings; spreadsheet-oriented CSV is a flat metric report with repeated context and formula mitigation. No per-request browser endpoint exists.

Trust the local database, filesystem directory and process account. Disabling DuckDB external SQL access limits query capabilities; it does not turn hostile database files into safe inputs. The projection reduces retained data but is not a guarantee of anonymity. Filesystem encryption, operating-system permissions, backup policy and deletion of private captures remain outside the package. Never publish real captures or database files merely to reproduce the aggregate demo.

The collector's before/after counts and update markers detect some live-source changes, not every concurrent modification. A `complete` collector manifest means bounded checks agreed, not an atomic, authenticated export. User-supplied manifests are unattested. Closure fractions are descriptive administrative outcomes under the recorded observation window, not causal service-quality or real-world resolution measures. The [data contract](DATA_CONTRACT.md), [public finding](PUBLIC_FINDINGS.md) and [measurements](MEASUREMENTS.md) state the respective limits.
